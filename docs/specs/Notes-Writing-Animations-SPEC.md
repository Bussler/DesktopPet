# Notes Writing Animations - Feature Specification

## Problem Statement

People writing in Hood Notes want their pet to write alongside them. Keeping a note focused does not mean the person is typing, so focus alone must not start or sustain the animation. The response should feel continuous between keystrokes, fit each pet's character, and leave normal care, sleep, and direct interactions intact. Users also need a separate way to disable this response without changing idle animations.

## Solution

Add **Play writing animations** to Hood Settings as an independent, enabled-by-default behavior option. While the user types in a note's content, title, or formula source editor, the selected pet performs its own writing animation: Hood and Pip write in notebooks, Crumb types on a keyboard, and Puddle writes on the ground.

Characters, Enter, Tab, Backspace/Delete, and keyboard paste start or sustain writing. Navigation, modifier-only keys, mouse actions, and typing in search or settings do not. Start on the first qualifying keystroke, continue smoothly across subsequent keystrokes, and return to normal behavior after **0.8 seconds** without one. Leaving the editing field stops writing immediately, even if the note window remains focused.

Writing temporarily pauses roaming and replaces idle gestures. Sleeping, feeding, dragging, and click reactions retain priority. A higher-priority action can be followed by writing only while qualifying typing remains current. Existing Focus reminders and break sleep retain their established behavior.

## Implementation Decisions

- **Boundaries:** Retain the portable `DesktopPet.Core` behavior/configuration contracts and the `DesktopPet.Windows` ownership of WPF input, window lifecycle, and rendering. Extend the existing Notes-to-app-to-overlay coordination rather than creating a second pet controller or editor. Keep input classification and temporary activity small and explicit; reuse existing elapsed-time and presentation mechanisms where appropriate.
- **Input contract:** Recognize keyboard activity only in a note's content editor, title, and inline/display formula source controls, including embedded editors. Character input, Enter, Tab, Backspace/Delete, and supported keyboard paste qualify. Modifiers alone, navigation, selection/formatting/undo commands alone, mouse paste, other mouse actions, search, and settings do not. Modifiers used to enter characters do not disqualify those characters. Preserve existing editing commands, text composition, and clipboard behavior; a qualifying key does not have to produce a different saved document to count. Do not infer typing from generic content-change events, which also occur during loading, formatting, and recovery.
- **Timing and ownership:** A qualifying keystroke creates a transient activity window ending 800 milliseconds after the latest qualifying input. Start presentation at the next normal UI/render opportunity; keep animation phase continuous across keys and loop while eligible. At the deadline, writing ends at the next normal update rather than waiting for the loop to finish. Use monotonic elapsed time with a deterministic test boundary, not wall-clock timestamps or delayed per-key work. Only the currently focused eligible field may sustain activity. Losing that field's keyboard focus clears its activity immediately; entering another field requires new input. A stale focus/close callback from a former field must not clear newer activity owned by the current field.
- **Lifecycle:** Clear temporary activity on note close/hide/delete, sprite hiding, application suspension, and shutdown. Do not queue hidden input or restore it on reveal, resume, or restart. Ordinary appearance refreshes must not manufacture input. Changes to pet selection or previews preserve existing Save/Cancel behavior and never reuse another pet's frames. The new writing setting is not a reason to show hidden sprites, activate the overlay, move focus, or create additional windows.
- **Presentation and priority:** Writing may replace idle gestures and temporarily suppress roaming without changing its saved toggle, bounds, or position. Stop moving while writing; release only the suppression owned by writing when it ends, allowing normal session scheduling to continue. Sleep, feeding, dragging, click reactions, and established Focus/checklist overrides retain their existing precedence and lifecycle. Normal active Focus time permits writing; its completion wave and break sleep retain their current contracts. Do not defer automatic naps or alter need progression to keep writing visible. After a higher-priority action ends, present writing only if the eligible field still owns unexpired typing activity. Do not queue a delayed writing action or restart a finished higher-priority action.
- **Independent configuration:** Add a boolean `WritingAnimations` behavior preference serialized as `behavior.writing_animations`, with a default of `true` when absent. The preference is independent of `IdleAnimations`, roaming, random events, and media headphones. Explicit saved `true` and `false` values round-trip. Extend the existing configuration validation/default generation and Settings behavior workflow; no configuration schema-version bump is needed for this additive optional field. Preserve unrelated explicit values and existing invalid-input handling.
- **Settings interaction:** Place the **Play writing animations** checkbox with the existing behavior options. Use the current theme, accessibility, and keyboard conventions. Apply the behavior preference through Save; Cancel or closing without saving retains the previous effective value. Preserve the existing save-failure reporting and rollback. Applying disabled clears writing immediately; applying enabled waits for new input. No new preview workflow, separate per-pet toggles, timeout control, or typing-speed control is required.
- **Artwork:** Provide genuine, distinct writing sequences for all four built-in pets: Hood and Pip with notebooks, Crumb with a keyboard, and Puddle writing on the ground. Match each pet's established design, scale, pose anchoring, and transparency; keep props inside valid frame/motion bounds. Preserve existing actions and their frame identities. Extend existing packing, manifests, playback validation, previews, and headphones/earbud pose support as necessary. Choose frame count and cadence during artwork work to make the motion smooth and recognizable; the agreed 800-millisecond activity timeout is independent of loop duration. This specification does not fix an unreviewed frame count or drawing technique.
- **Artwork compatibility:** Adding a writing action must not make previously supported replacement manifests invalid solely because they omit it. For valid legacy/custom artwork without a writing sequence, use its existing idle artwork for the temporary presentation, respecting idle-animation settings for that fallback. The typing window and temporary roaming pause still expire normally. Built-in assets must supply the real custom sequences; the fallback is not an alternative to delivering them. Keep all existing asset validation and recovery for genuinely missing or corrupt required resources. Preserve prior action identifiers and saved-frame compatibility.
- **Persistence and privacy:** Persist the option through the authoritative YAML configuration only. Typing ownership, expiry, animation phase, and temporary suppression are runtime state; do not save or restore them as a pet action or change Notes/session schemas. Existing saved notes, session continuation, safe replacement writes, and recovery remain valid. Animation notification needs only activity and ownership, with no captured text, keystroke history, global keyboard hook, network access, or additional privilege.
- **Failure boundaries and scope:** The response must not consume editor input, perform additional note saves, change accepted content, reset undo, or replace existing save/retry feedback. Keep rendering at existing boundaries; report genuine asset errors through current handling. Avoid new dependencies, a general input-monitoring service, a new asset format, or an animation scheduling redesign. Implementation remains a separate task from publishing this document.

## Testing Decisions

- **Confirmed plan:** The user confirmed application behavior from Notes input through app wiring to observed pet presentation with controlled time; supporting settings/asset checks; and separate physical-keyboard and visual acceptance against a packaged executable. Exercise externally visible outcomes rather than private callback counts or a duplicate model of the implementation.
- **Primary application boundary:** Extend the existing Windows STA interaction approach to connect real Notes editing controls, app-owned activity coordination, the selected pet's overlay, and the session. Drive character composition, key events, keyboard paste, focus changes, and lifecycle commands through their actual routing. Assert displayed action/frame progression, position, normal behavior after expiry, and unchanged editing results. Testing a standalone input classifier or calling the overlay directly cannot alone establish that Notes is connected to the pet.
- **Prior art:** Reuse the patterns in `NoteInteractionTests`, `NoteTypingRecognitionTests`, and the inline/display math interaction tests for editor actions and embedded focus; `HoodOverlayRenderingTests` for observable presentation across all pets; `FocusInteractionTests` for timed presentation overrides and app wiring; `SettingsAndStatsTests` for behavior-setting transactions; `HoodConfigurationTests` and session-persistence tests for defaults, round trips, and compatibility; and `HoodAssetsTests`/`MediaHeadphoneArtworkTests` plus existing sprite validators for resource and compositing contracts. Add focused lower-level cases only where they improve determinism or explain a real boundary failure.
- **Input matrix:** Cover content, title, both formula source editors, empty notes, ordinary rich text, lists/code/tables, held-key repetition, character modifiers, Enter/Tab, Backspace/Delete, and supported keyboard paste. Include negative cases for focus only, modifiers alone, navigation, selection/formatting/undo commands alone, mouse paste, searches/settings, programmatic document loads, and automatic rendering updates. Verify that nonqualifying activity neither starts writing nor renews its deadline, and that ordinary edits still save and undo correctly.
- **Time and ownership:** Control elapsed time rather than sleeping for assertions. Check initial activation; repeated keys extending the deadline without restarting the cycle; just before, at, and after 800 milliseconds; immediate focus loss; transitions between content/title/formula controls and between notes; a stale callback from an old owner; and immediate close/hide/delete. Verify that disabling, hiding sprites, suspend/resume, and Quit/restart remove stale activity and leave no stuck suppression or pending response.
- **Priority and continuation:** Observe writing taking over idle and interrupting roaming, including unchanged position during the active interval and normal roaming eligibility afterward. Verify sleeping, automatic nap onset, feeding, drag, click/wake reactions, checklist celebration, Focus completion waving, and Focus break sleep retain priority. Test both fresh typing during a higher-priority action and expiry before it ends; only unexpired input with current field ownership may resume writing. Existing needs, sleep, and saved roaming preferences must remain governed by their prior contracts.
- **Settings and persistence:** Test the four combinations of idle/writing preferences, writing with roaming/random events disabled, and visible/hidden sprites. Verify new and missing-field defaults, explicit false/true round trips, valid boolean/invalid-value handling, actual YAML save/reload, Save, Cancel, close without saving, failed Save, and unrelated-value preservation. Check that the checkbox uses the expected label and normal accessible keyboard behavior. Confirm that transient typing never changes the durable session/Notes format or restores as writing after restart.
- **Assets and rendering:** Parameterize built-in coverage across Hood, Pip, Crumb, and Puddle. Validate loadable custom writing sequences, frame/crop bounds, timing/loop behavior, unchanged logical dimensions and existing action contracts, previews, and packaged resource availability. Verify representative writing frames with and without media accessories, including body/prop alignment and visible layers. Test a previously valid manifest with no writing action and the existing missing/corrupt-resource paths. Contract/render checks cannot establish that a notebook, keyboard, or ground-writing movement looks convincing to a person.
- **Native acceptance:** Use an identified packaged executable, recording its path and build identity. Physically type, delete, paste by keyboard and mouse, navigate, switch fields/notes/apps, and pause at natural typing speeds. Inspect all four distinct animations, first-key response, phase continuity, immediate focus-loss stop, return to idle/roaming, higher-priority interactions, and independent toggles. Check identity, readable props, headphones/earbud fit, transparency, clipping, scale, and monitor/DPI transitions at supported pet sizes. Confirm that Notes retains focus and responsive editing. Automated WPF/render tests do not substitute for these visual and physical-input checks.
- **Completion evidence:** For future implementation, run the relevant interaction, configuration, session, asset/render, and sprite checks through the project's explicit test workflow, then build/package through the existing publishing workflow. A package build alone does not prove tests ran. Record automated results separately from native acceptance and any remaining gaps. This documentation change requires specification/content/link checks; it does not require an app build or claim that feature tests already pass.

## Out of Scope

- Responding to typing in other applications, global keyboard monitoring, search/settings fields, mouse-only editing, or focus without typing.
- Coupling writing to idle animations, per-pet enable switches, extra timeout/speed controls, typing sounds, or changing the established 0.8-second inactivity rule.
- Replacing existing idle, roaming, click, petting, feeding, sleep, Focus, or checklist behavior beyond the temporary writing response and its specified priority.
- Changing care gains, needs, note content/formatting/history, keyboard shortcuts, clipboard contracts, focus ownership, storage schemas, or recovery behavior.
- Requiring third-party/custom artwork creators to add writing poses for existing supported assets to remain usable, or promising custom accessory fit for arbitrary redesigned characters.
- Generating artwork, implementing the feature, creating tickets, building a candidate, or publishing an external issue as part of creating this specification.
